Another tokio is already on this port

Port 4646 is answered by a tokio this app cannot authenticate with, so it has nothing to show yet.

On Windows this is almost always tokio running inside WSL. WSL forwards localhost, so a daemon over there answers here as though it were local — but its access token stays in its own config, where this window cannot read it.

That daemon has your real history in it. Point this window at it and everything works; there is nothing to move or copy.

Run tokio inside WSL and it prints this line.

Prefer to keep them separate? Change port in this machine's tokio config and reopen — this window will start a daemon of its own.
